# Quick Start Guide

## TL;DR - Get Running in 3 Steps

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. Run quick test (Windows)
run_quick_test.bat

# OR manually (any OS):
python run_analysis.py --num-examples 3

# 3. View results
python view_results.py
```

## What This Does

This tool helps you understand how the Qwen2.5-Coder model performs on APPS coding problems with and without hints:

1. **Qwen2.5-Coder-3B-Instruct (no hints)**: Direct code generation
2. **Qwen2.5-Coder-3B-Instruct (with frozen hints)**: Code generation with hints from Qwen2.5-3B-Instruct

**The Process:**
- Instruct model (Qwen2.5-3B-Instruct) generates a hint about the approach
- Coder model generates code WITHOUT the hint
- Coder model generates code WITH the frozen hint injected

Before doing supervised fine-tuning, you need to see:
- Whether frozen hints from the Instruct model help the Coder model
- How the Coder model performs with and without guidance
- How outputs compare to reference solutions
- If hints should be part of your fine-tuning training data

## Common Commands

### First Time Setup
```bash

pip install -r requirements.txt

# Verify it works
python test_setup.py
```

### Run Analysis
```bash
# Quick test (3 examples)
python run_analysis.py --num-examples 3

# More examples (10)
python run_analysis.py --num-examples 10

# Use CUDA if available
python run_analysis.py --num-examples 5 --device cuda

# Test split instead of train
python run_analysis.py --num-examples 5 --split test
```

### View Results
```bash
# Summary of all examples
python view_results.py

# Detailed view of example 1
python view_results.py --example 1

# Side-by-side comparison
python view_results.py --compare 1

# Include prompts used
python view_results.py --example 1 --verbose

# Export to markdown
python view_results.py --export-md my_report.md
```

## Understanding the Output

### Console Output
During analysis, you'll see:
- ✓ Progress indicators
- Problem statements (truncated)
- Generated hints
- Model outputs (truncated)
- Canonical solutions (truncated)

### JSON Output
The `apps_analysis_results.json` file contains:
- Full problem descriptions
- Complete generated code from both models
- Hints generated by the instruct model
- Canonical solutions from APPS
- Prompts used for each generation
- Metadata (timestamp, models used, etc.)

### What to Look For

1. **Code Quality**
   - Is the code syntactically correct?
   - Does it follow good practices?
   - Is the logic sound?

2. **Hint Effectiveness**
   - Does the hint capture the key approach?
   - Does the Coder model actually use the hint?
   - Does the hint improve the Coder model's output quality?

3. **Performance Comparison**
   - Does the Coder model produce better code with hints?
   - Which approach handles different difficulty levels better?
   - Are there patterns in when hints help vs hurt?

4. **Fine-tuning Insights**
   - What prompt format works best?
   - Should you include hints in training data?
   - How should you structure the training examples?

## Troubleshooting

### Out of Memory
```bash
# Use CPU instead
python run_analysis.py --device cpu --num-examples 3

# Or reduce examples
python run_analysis.py --num-examples 2
```

### Models Download Slowly
- First run downloads ~6GB of models
- Be patient, this is one-time
- Models cache in `~/.cache/huggingface/`

### APPS Dataset Issues
```python
# The dataset downloads on first use
# If it fails, try:
from datasets import load_dataset
load_dataset("codeparrot/apps", split="train")
```

### Import Errors
```bash
# Reinstall requirements
pip install -r requirements.txt --force-reinstall
```
